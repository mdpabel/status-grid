When a page disappears, the right response depends on whether it has a useful replacement. Your goal is to give people and crawlers an honest answer, while preserving a path to content that still helps.

## 404: the resource is not here

`404 Not Found` is appropriate when the requested URL has no available resource. A custom 404 page can help visitors recover with search and useful links, but the **HTTP response still needs to be 404**. Google's [crawling error guidance](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors) explicitly recommends returning 404 for a genuine missing page.

Do not treat every 404 as a crisis. Old URLs, typing mistakes, and expired content exist on every sizable site. Prioritize 404s linked from your own pages, included in your sitemap, or requested frequently by real users.

## 410: the removal is intentional

`410 Gone` explicitly says the resource is no longer available and the condition is expected to be permanent. It can be a clear response for deliberately retired content. In Google's [status-code documentation](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes), both 404 and 410 fall into the group of 4xx pages that are not processed for indexing. Choose the code that accurately reflects your situation; don't expect a dramatic SEO difference from swapping one for the other.

## Soft 404: the code and content disagree

A **soft 404** is a page that responds successfully, often with `200 OK`, but appears to be an error or empty result. Examples include a product template that says “item unavailable” with no meaningful content, or a missing URL that shows a generic error screen while returning 200.

Google says its systems can identify these pages and report them as soft 404s in Search Console. A status checker can reveal the HTTP 200; it cannot reliably decide whether the rendered page is a soft 404. Review the page content and Search Console report to make that call.

## Should you redirect instead?

Redirect when there is a genuinely relevant replacement. A retired guide with a newer edition may have a clear target. A deleted product might have a close successor. If no close match exists, a helpful 404 or 410 is more honest than sending every old URL to the homepage.

## A simple decision path

1. **The page should still exist:** restore it, fix the route, and return 200.
2. **There is a close permanent replacement:** redirect to that replacement and check the final destination.
3. **The page is intentionally gone with no replacement:** return 404 or 410 and remove internal links and sitemap entries.
4. **The page is temporarily unavailable:** keep the intended URL and use an appropriate temporary response while resolving the issue.

After the change, [check your affected URL list](/#checker) again. Confirm the final response, not just the first hop.
